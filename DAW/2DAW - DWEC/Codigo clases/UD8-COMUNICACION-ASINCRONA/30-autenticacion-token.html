🔐 Autenticación con Bearer Token

¿Qué es la Autenticación?

Autenticación = Demostrar quién eres ante el servidor.

Las APIs privadas requieren que te identifiques en cada petición.

🎫 Bearer Token

Authorization Header

Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

⬆️ Este token identifica al usuario

🎟️

¿Qué es?

Una cadena de texto que prueba tu identidad

🔑

¿De dónde sale?

El servidor te lo da cuando haces login

📤

¿Cómo se usa?

Lo envías en el header Authorization

⏰

¿Cuánto dura?

Tiene fecha de expiración (ej: 1 hora, 1 día)

🔄 Flujo Completo de Autenticación

1

Login

POST /login

{ username, password }
↓
2

Servidor devuelve token

Response

{ token: "abc123..." }
↓
3

Guardar token

localStorage

localStorage.setItem('token', ...)
↓
4

Usar en peticiones

Header Authorization

Bearer ${token}

🎯 Ejercicio 10: Flujo de autenticación

Vamos a simular el flujo completo: login → guardar token → usar token en peticiones.

Vamos a programar:

  1. login(): Simular POST a /login (devuelve token falso)
  2. guardarToken(): Guardar en localStorage
  3. hacerPeticionAutenticada(): GET con header Authorization
  4. flujoCompleto(): Ejecutar los 3 pasos en orden

Abre la consola (F12) y Application → Local Storage para ver el token guardado.

Formato del header Authorization:

headers: {
    'Authorization': `Bearer ${token}`
    //                ↑      ↑
    //             palabra  espacio + token
}

📊 Códigos HTTP de Autenticación

200 OK

✅ Autenticación correcta, token válido

401 Unauthorized

❌ Token inválido, expirado o no enviado

→ Hacer login de nuevo

403 Forbidden

❌ Token válido pero sin permisos

→ Mostrar error al usuario

⚠️ IMPORTANTE: El prefijo Bearer con espacio después es obligatorio: "Bearer token123"
