🔧 PATCH: Actualización Parcial

Diferencia: PUT vs PATCH

PUT = Actualizar TODO el recurso (enviar objeto completo)

PATCH = Actualizar SOLO lo que cambió (enviar solo campos modificados)

PUT

id: 1
title: "Nuevo título"
body: "Nuevo contenido"
userId: 1

Envío TODO el objeto, aunque solo cambien 2 campos

PATCH

title: "Nuevo título"

Solo envío el campo que cambió

📋 ¿Cuándo usar cada uno?

✅ Usa PUT cuando:

  • Tienes todo el objeto disponible
  • Formulario de edición completo
  • Quieres reemplazar el recurso entero

✅ Usa PATCH cuando:

  • Solo cambias 1 o 2 campos específicos
  • Toggle de estado (activo/inactivo)
  • Incrementar contador (likes, visitas)
  • Actualización rápida sin recargar todo

🎯 Ejercicio 6: Actualizar solo el título

Vamos a actualizar ÚNICAMENTE el título del post 1, sin tocar el resto de campos.

Endpoint: https://jsonplaceholder.typicode.com/posts/1

Vamos a programar:

  1. Función que actualiza solo el título (PATCH)
  2. Función para marcar como completado (PATCH)
  3. Función para incrementar likes (PATCH)

Abre la consola (F12) para ver cómo enviamos menos datos.

Estructura PATCH:

fetch(`/posts/${id}`, {
    method: 'PATCH',
    headers: {
        'Content-Type': 'application/json'
    },
    body: JSON.stringify({ 
        title: "Solo este campo" 
    })
})

💡 Ejemplos prácticos de PATCH

👍

Dar Like

{ likes: likes + 1 }
✅

Marcar completado

{ completed: true }
👁️

Incrementar vistas

{ views: views + 1 }
🔒

Cambiar privacidad

{ private: false }
💡 Ventaja: PATCH es más eficiente porque envía menos datos. Útil en conexiones lentas o móviles.
