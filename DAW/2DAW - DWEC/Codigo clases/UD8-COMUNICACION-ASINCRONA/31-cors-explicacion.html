🌐 CORS: Cross-Origin Resource Sharing

¿Qué es CORS?

CORS = Política de seguridad de los navegadores.

Controla qué dominios pueden acceder a qué APIs.

🎯 ¿Qué es un "Origen"?

Anatomía de una URL:

https:// Protocolo
miapp.com Dominio
:3000 Puerto
/api/posts Path

ORIGEN = Protocolo + Dominio + Puerto

https://miapp.com:3000

✅ ❌ Ejemplos de CORS

✅

MISMO ORIGEN - OK

Tu web: https://miapp.com/page1

API: https://miapp.com/api/posts

✅ Sin problemas de CORS

❌

DIFERENTE DOMINIO

Tu web: https://miapp.com

API: https://api.ejemplo.com

❌ Error CORS (si no está permitido)

❌

DIFERENTE PUERTO

Tu web: http://localhost:3000

API: http://localhost:8080

❌ Error CORS (diferente puerto)

❌

DIFERENTE PROTOCOLO

Tu web: http://miapp.com

API: https://miapp.com

❌ Error CORS (http vs https)

🔄 ¿Cómo funciona CORS?

1

Tu JavaScript hace fetch

fetch('https://api.ejemplo.com/posts')
↓
2

El navegador verifica el origen

"¿De dónde viene esta petición?"

↓
3

Servidor responde con headers CORS

Access-Control-Allow-Origin: *
↓
4

Navegador decide

✅ Origen permitido

→ Te da los datos

❌ Origen no permitido

→ Error CORS

📋 Headers CORS importantes

Access-Control-Allow-Origin

Access-Control-Allow-Origin: *

Permite cualquier origen

Access-Control-Allow-Origin

Access-Control-Allow-Origin: https://miapp.com

Permite solo ese dominio específico

Access-Control-Allow-Methods

Access-Control-Allow-Methods: GET, POST, PUT

Métodos HTTP permitidos

Access-Control-Allow-Headers

Access-Control-Allow-Headers: Content-Type, Authorization

Headers permitidos en las peticiones

🎯 Ejercicio 11: Verificar CORS

Vamos a hacer una petición a JSONPlaceholder y analizar los headers CORS que envía.

API: https://jsonplaceholder.typicode.com/posts/1

Vamos a:

  1. Hacer petición GET a la API
  2. Analizar header Access-Control-Allow-Origin
  3. Ver otros headers CORS disponibles
  4. Explicar por qué funciona sin errores

Abre la consola (F12) y la pestaña Network para ver los headers CORS.

🔧 Soluciones a errores CORS

✅ SOLUCIÓN CORRECTA

El backend añade headers CORS

El servidor debe configurar los headers correctamente

⚠️ SOLUCIÓN TEMPORAL (desarrollo)

Proxy en desarrollo

Herramientas como Vite, Webpack tienen proxy que evita CORS en local

❌ SOLUCIÓN INCORRECTA

Plugins de navegador

Desactivan CORS pero SOLO en tu navegador. No funciona para otros usuarios.

💡 Importante: CORS es una protección del NAVEGADOR. Las peticiones desde backend (Node.js, Python) no tienen este problema.
