1. EXPRESIONES REGULARES (PATRONES ESPECÍFICOS)

Patrones completos para copiar:
Email básico: /^[^\s@]+@[^\s@]+\.[^\s@]+$/
Teléfono (9 dígitos): /^\d{9}$/
DNI (8 dígitos + letra): /^\d{8}[A-Z]$/
Código postal: /^\d{5}$/
Contraseña (min 8, 1 may, 1 min, 1 num): /^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}$/
Solo letras: /^[a-zA-Z]+$/
Solo números: /^\d+$/
Fecha (DD/MM/YYYY): /^\d{2}\/\d{2}\/\d{4}$/
Letras y espacios: /^[a-zA-Z\s]+$/
Símbolos RegEx de referencia:
^ → Inicio | $ → Final | \d → Dígito (0-9) | \s → Espacio | \w → Letra/dígito/_
[A-Z] → Mayúscula | [a-z] → Minúscula | [0-9] → Dígito
{n} → Exactamente n | {n,} → Mínimo n | {n,m} → Entre n y m
+ → 1 o más | * → 0 o más | ? → 0 o 1
(?=.*[A-Z]) → Lookahead: debe contener al menos una mayúscula
[^abc] → Cualquier carácter EXCEPTO a, b, c

2. HTTP STATUS CODES (CÓDIGOS DE ESTADO)

200 OK → Petición exitosa
201 Created → Recurso creado exitosamente
204 No Content → Exitoso pero sin contenido en respuesta
400 Bad Request → Datos inválidos o mal formateados
401 Unauthorized → No autorizado (falta token/login)
403 Forbidden → Prohibido (no tienes permisos)
404 Not Found → Recurso no encontrado
500 Internal Server Error → Error del servidor
503 Service Unavailable → Servicio no disponible

3. FETCH API - CONFIGURACIÓN DETALLADA

Estructura completa del objeto options:
fetch(url, {
  method: "POST", // GET, POST, PUT, DELETE
  headers: {
    "Content-Type": "application/json",
    "Authorization": "Bearer TOKEN"
  },
  body: JSON.stringify(datos) // Solo POST/PUT
})
Headers comunes:
"Content-Type": "application/json"
• Indica que enviamos JSON (POST/PUT)

"Content-Type": "application/x-www-form-urlencoded"
• Indica que enviamos formulario tradicional

"Authorization": "Bearer TOKEN"
• Token de autenticación JWT

"Accept": "application/json"
• Indica que aceptamos recibir JSON
Propiedades del objeto Response:
response.ok → true si status 200-299, false si no
response.status → Código numérico (200, 404, etc.)
response.statusText → Texto del status ("OK", "Not Found")
response.headers → Headers de la respuesta
response.json() → Convierte body a JSON (devuelve promesa)
response.text() → Convierte body a texto (devuelve promesa)
Ejemplos de peticiones por método:
POST (crear):
fetch(url, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(datos)
})

PUT (actualizar completo):
fetch(`${url}/${id}`, {
  method: "PUT",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(datosActualizados)
})

DELETE (eliminar):
fetch(`${url}/${id}`, { method: "DELETE" })

Con Authorization (Bearer Token):
fetch(url, {
  headers: { "Authorization": `Bearer ${token}` }
})

4. MÉTODOS ESTÁTICOS DE PROMISE (AVANZADOS)

Promise.all([promesa1, promesa2, ...])
  • Espera a que TODAS las promesas se resuelvan
  • Si una falla, todas fallan
  • Devuelve array con todos los resultados
Promise.race([promesa1, promesa2, ...])
  • Devuelve la primera promesa que se resuelve (la más rápida)
  • Útil para timeouts
Promise.allSettled([promesa1, promesa2, ...])
  • Espera a que todas terminen (éxito o fallo)
  • Devuelve array con status de cada una

5. OBJETO ERROR - PROPIEDADES

error.message → Mensaje descriptivo del error
error.name → Tipo de error ("TypeError", "ReferenceError", "SyntaxError", etc.)
error.stack → Traza completa del error (línea, archivo, etc.)
Tipos de errores nativos de JavaScript:
Error → Error genérico
TypeError → Error de tipo (ej: null.metodo())
ReferenceError → Variable no definida
SyntaxError → Error de sintaxis en el código
RangeError → Valor fuera de rango permitido

6. MÉTODOS DE ARRAY (REFERENCIA RÁPIDA)

array.find(callback) → Devuelve EL PRIMER elemento que cumple condición
array.findIndex(callback) → Devuelve ÍNDICE del primer elemento que cumple
array.some(callback) → true si AL MENOS UNO cumple la condición
array.every(callback) → true si TODOS cumplen la condición
array.includes(valor) → true si el array contiene ese valor
array.indexOf(valor) → Índice de la primera aparición (-1 si no existe)
